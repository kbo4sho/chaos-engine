# First repair on a phone

The online workbench loads its game code and Matter.js in two scripts. A WOFF2 copy of VT323 includes the full original character set. The film encoder and the machine press worker load when the player needs them.

## Sub-features

- The same bundled game serves the numbered campaign, workshops and challenges. Each published change gives the entry script a new version in its address.
- The local server compiles current source changes when the entry is requested. Its compressed response uses a content-based validator. With a plain Node installation the preview can use the original source modules.
- Downloaded machines and studies embed their source modules and the WOFF2 font. Their normal offline playback remains available.
- The build refreshes the public bundle. CI verifies the committed publication files against a fresh build.

## How to get to it (user POV)

Open One Part Missing from the Chaos Engine header. Fit a bridge at the first socket. Generate a machine from the press or export a film when you want to use those tools.

## Driving it with verify-chaos-engine

Preconditions: launch and doctor pass with a fresh profile. Run `./scripts/verify-chaos-engine drive phone-startup`.

Cold-load the game three times at phone size with cache disabled, 150 ms of latency, 1.5 Mbps downstream and fourfold CPU slowdown. Fit a real spare each time and record resource sizes, working controls and the time the sockets appear. Win a delivery, make a comparison GIF and generate a new machine using the native worker.

## Gotchas

Measurements depend on the browser, device and connection. Resource counts apply to the first ordinary repair. A direct link to a printed machine starts its worker during setup. Offline files carry their own code and use their own asset count.
